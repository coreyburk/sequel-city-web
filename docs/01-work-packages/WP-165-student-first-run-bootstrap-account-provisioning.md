# WP-165: Student First-Run Bootstrap Account Provisioning

## Objective

Reduce student setup friction by making the packaged launcher create or repair Sequel City SQL accounts through the existing Windows-integrated bootstrap path when local permissions allow it, while keeping destructive database rebuilds explicit and instructor-controlled.

## Scope

### In Scope

- Update the student package launcher so a normal pilot tester does not need to know or type the `sequel_web_user` password during first run.
- Generate `apps/api/.env` with the expected local classroom account values and bootstrap mode defaults needed for first-run account provisioning.
- Add a clear first-run bootstrap/account-provisioning preflight in the launcher, using the existing API bootstrap behavior where possible.
- Add an instructor/admin fallback script or launcher path for local SQL account provisioning when automatic Windows-integrated setup fails.
- Keep full `SequelCityCrimesDB` rebuild/drop/create behind explicit confirmation because `database/01-SequelCityCrimesDB - Create DB.sql` is destructive.
- Update student and instructor package docs so the normal student path is extract package, double-click launcher, and report any bootstrap failure message.
- Update packaging script contents if new launcher/helper scripts must be included in the package.

### Out of Scope

- No SQL Server installer automation.
- No TCP/IP or SQL Server Configuration Manager automation unless already available through a safe read-only check.
- No production hosting or cloud deployment changes.
- No runtime AI, account/session model, or student identity system.
- No broad rewrite of the API bootstrap architecture.
- No unconditional database drop/recreate on startup.
- No change to Case 004 data, guidance, answer keys, or student progression.

## Constraints

- Preserve existing bootstrap behavior unless explicitly improving first-run account provisioning for student packages.
- Do not require students to know SQL passwords that the application can own and generate itself.
- Do not run destructive database scripts without an explicit confirmation prompt that names `SequelCityCrimesDB` and states it will be dropped/recreated.
- Do not hide SQL Server installation or configuration prerequisites.
- Do not expose hidden case answers or answer-key data in health messages, launcher output, or docs.
- Do not add new npm dependencies.
- Do not weaken runtime SQL safety or give `sequel_web_user` write/admin permissions.
- Preserve production-safe behavior: automatic Windows-integrated provisioning is local/non-production only.
- Keep changes compatible with WP-163's future database identity and gated rebuild work.

## Required Behavior

- The student launcher should create `apps/api/.env` using local defaults without requiring a student-entered app SQL password:
  - `SQLSERVER_HOST=localhost`
  - `SQLSERVER_PORT=1433`
  - `SQLSERVER_DATABASE=SequelCityCrimesDB`
  - `SQLSERVER_USER=sequel_web_user`
  - the project-owned runtime password expected by `databaseBootstrapService`
  - `SQLSERVER_TRUST_SERVER_CERTIFICATE=true`
  - a bootstrap mode/default that allows local first-run provisioning where safe
- When `.env` already exists, the launcher should preserve it unless the user explicitly chooses to regenerate it.
- The first-run path should let the API bootstrap create or repair:
  - SQL login `sequel_web_user`
  - database user `sequel_web_user`
  - `db_datareader` membership for `sequel_web_user`
  - SQL login `sequel_bootstrap_user`
  - database user `sequel_bootstrap_user`
  - `db_owner` membership for `sequel_bootstrap_user`
- If automatic provisioning fails, the user-facing error should be short and actionable:
  - tell the student to send the message to the instructor
  - point the instructor to the fallback setup script or Admin Mode path
  - avoid raw credentials and spoilers
- If a helper script is added, it must be idempotent and safe to rerun against an already-provisioned local database.
- If a database rebuild path is added or exposed, it must:
  - be opt-in
  - show a destructive warning
  - require a typed or explicit confirmation
  - run only against the local configured database name
  - not run during normal startup
- The student docs should describe the simplified flow as:
  1. install prerequisites
  2. extract package
  3. double-click `Start-SequelDetective.cmd`
  4. check Health Status
  5. send the bootstrap failure message to the instructor if setup cannot finish
- Instructor docs should state the fallback admin action clearly and distinguish account provisioning from destructive database rebuild.
